# CapCut-Style Manual Timeline Editor for ClipForge

## Goal
Turn the clip edit page (`/dashboard/projects/[id]/clips/[clipId]` — reached from the project preview page's "Edit clip" button) from number-input editing into a **visual, CapCut-style timeline editor**:

- **Filmstrip timeline** with canvas-captured video thumbnails
- **Draggable trim handles** (in/out) over the **original source video** — move/extend the clip window anywhere (today it's only numeric start/end inputs)
- **Scrubbable playhead** synced to a preview player that loops within the selected window, plus "Set in / Set out" buttons
- **Track lanes** with draggable + resizable blocks: Captions and B-roll (Music lane read-only, it's project-level)
- **Auto-fill captions** for a newly trimmed window from the project's word-level transcript
- Existing cards (caption text list, caption style, B-roll search/picker, music) stay and share state with the timeline — edit in either place, both stay in sync

Rendering still happens in the existing pipeline (Shotstack); the editor writes the same data the backend already accepts.

## Key facts driving the design (verified in code)
- `clips.start_time/end_time` are in **source-video coordinates**; SRT cues and `broll_json` segments are **clip-relative** (0 = clip start) (`worker/src/pipelines/render.js`, `worker/src/lib/broll.js`)
- Min clip length 3s; b-roll max 8 segments (already enforced by backend)
- No endpoint currently serves the source video to the browser — one must be added
- Split uploads (>40 MB) store a `manifest.json`, not a playable file — degraded mode needed

## Changes

### 1. Backend — expose the source video (`backend/src/routes/clips.js`)
Add `GET /api/clips/:id/source-playback` (requireAuth, ownership-checked):
- Join the clip's project `original_video_path`; sign it from the `source-videos` bucket (60-min expiry)
- Returns `{ video_url, split: false, duration }`, or `{ video_url: null, split: true, duration }` when the path ends in `/manifest.json`

### 2. New frontend helpers (`frontend/lib/timeline.ts`)
`formatTimecode`, ruler tick-step math, 0.1s snapping, clamp helpers, and `cuesFromTranscript(words, clipStart, clipEnd)` that groups word-level transcript entries into caption cues (≤ ~42 chars / ≤ 3.5 s) for the auto-fill button.

### 3. New component — `frontend/components/dashboard/timeline-editor.tsx`
Self-contained client component. Props: `videoUrl`, `sourceDuration`, `start`, `end`, `onTrim`, `cues`, `onCuesChange`, `broll`, `onBrollChange(commit)`, `musicTitle`.

- **Transport row**: play/pause, mute, timecode, "Set in"/"Set out", loop-in-window toggle (default on), zoom −/+ (px per second)
- **9:16 preview** playing the source video (this is the editing canvas); the existing "Final render / Raw trim preview" card stays in the left column to check the rendered result
- **Ruler + filmstrip + playhead**: horizontally scrollable; click/drag scrubs. Thumbnails captured progressively from a hidden `crossOrigin="anonymous"` video via canvas (kept separate from the playback video so CORS can never break playback); graceful fallback to plain blocks if capture fails
- **Trim handles**: pointer-drag, min 3 s, clamped to `[0, duration]`; filmstrip regenerates (debounced) on release
- **Captions lane**: cue blocks at `start + cue.start → start + cue.end`, drag to move / edges to resize, snapped 0.1 s, clamped inside the window
- **B-roll lane**: same drag/resize + delete on hover; local state during drag, persisted via the existing `/api/clips/:id/broll/segments` endpoint once on pointer-up; shows an "Auto (AI)" hint when b-roll is null
- **Music lane**: read-only bar
- Playhead updates via rAF + direct DOM style mutation (no per-frame React re-renders)
- Degraded mode when `video_url` is null (split uploads): handles/ruler/lanes still work, scrub and filmstrip disabled with a small explanatory note

### 4. Page integration (`frontend/app/dashboard/projects/[id]/clips/[clipId]/page.tsx`)
- Fetch source playback on mount; switch `startTime/endTime` to numeric state shared by the timeline and compact numeric readouts (precision editing kept)
- On window change: cues stay anchored to source time; if cues fall outside the window show a hint with **Auto-fill from transcript** and the existing **Reset to AI** actions; cues outside the window are dropped on save (counted in a toast)
- Save flow unchanged: same `/api/clips/:id/edit` endpoint (start/end + caption cues + style), b-roll via the segments endpoint
- Caption list editor, style controls, B-roll and Music cards unchanged except for two-way state sync with the timeline

### Out of scope (v1)
Splitting one clip into multiple clips, text/sticker overlays beyond captions, transitions, volume/mixing — the render pipeline doesn't support them yet.
